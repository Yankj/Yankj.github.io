> 「Web 限制」是最顺手的借口。我们把它从验收单里删掉了：少一个功能、多一步、明显更慢，都算不过。

前天早上，我在一个亲子类 App 的项目群里说：「把全部功能做一个web版本吧」，补了一句：「体验、功能不降级」。

这款 App 原本只有 iOS 版。说出「不降级」三个字很容易，难的是让一群 Agent 在几百个细节上都按这三个字做判断。因为几乎每一个细节，都有一个现成的借口：浏览器做不到，Web 本来就这样，小程序有限制。

负责统筹的 Agent 当场把这句话翻成了验收口径：「Web 上少一个功能、多一步操作，或者明显更慢，都直接算不过，不能当『Web 限制』放过去。」这句话后来成了整套验收的总则。

## 口号要拆成一行一行能判对错的条目

「不降级」如果只写在总则里，执行的时候还是会被一条条打折扣。所以验收单是按 iOS 的功能清单编号来写的，一项功能一行，每一行都要在桌面浏览器和手机浏览器上各判一次。

这样写出来的 Web 验收单有 148 行。另外还有一张四端对照表，33 行，覆盖 iOS、Web、小程序和安卓，以 iOS 为基准，其他每一端每一项都要写清：做了、没做、还是做法不同。

拆到这个粒度有个直接的好处：任何一个降级都藏不住。它要么在某一行被判 FAIL，要么被单独列出来，等我拍板。

## 拿不准的降级，一律列成「待用户定」

小程序那一端最先碰到这个问题。写代码的 Agent 在范围说明里写了「流式不行就改成整段返回」，还把生成卡通作品、调用设备能力这几项直接划成了「不做」。

负责验收的 Agent 和统筹的 Agent 都判它是降级：理由也许成立，但不能默认。后来这几项都被改成了「待用户定的降级项」，每一项旁边写着替代方案，比如流式回复做不到时用整段返回，提醒、朗读、语音、设备能力各自怎么退。

设计稿也按这个原则画：降级项照完整能力画，只在 App 框外标注。这样我看稿时，看到的是完整的产品，旁边清楚写着哪里可能打折，而不是一份已经被悄悄缩水的设计。

## 安全功能拿不准的时候，默认上锁

最能说明「不降级」有多难的，是闲置锁。

iOS 版闲置一段时间会上锁，解锁要过面容识别。Web 第一版的闲置锁是「点一下就开」。有 Agent 问，能不能按「同等减一档」接受。统筹的 Agent 判不接受：iOS 要过生物识别，Web 至少要重新走一遍第三方登录，而且回来的必须是同一个账号，才能解锁。

这一项后来被审了好几轮。每一轮都挖出一类新问题：锁住一段时间以后会自己失效；某些情况下根本不会锁；状态数据缺失或被改过时，判断会失效；本地清理数据被阻塞时，代码当成了成功。

最后沉淀下来的不是某个具体修法，而是一条原则：安全状态拿不准的时候，一律按锁住处理。数据缺失算锁，格式不对算锁，校验失败也算锁。小程序那端复验时也照这个口径，补上了前台闲置检查和切到后台时的遮罩；遮罩能不能挡住系统多任务界面的快照，还要等真机确认。另外，客户端请求里带了一个不该出现在客户端的密钥，被要求挪到服务端的转发层。

## 对话正文存在哪，推翻了两次

另一项是对话内容的存储。第一版把正文明文存在浏览器的本地存储里，被判不过。第二版改成只放在内存里，安全了，可一刷新就没了，体验又降级了。

第三版按我定的方向：本机加密保存，退出清空。落地是浏览器里的加密数据库，密钥按账号分开，而且不可导出；退出或者换账号，整个库删掉。

这个例子说明，「不降级」和「更安全」经常会打架。验收单的作用，是把这种冲突摆到桌面上，而不是让写代码的人自己选一个更省事的方向。

## 最大的分歧不在代码，在数据要不要上云

做多端对照的过程中，还暴露出一个更根本的问题。iOS 版里，孩子的资料、安排、目标、观察记录，都只存在手机本机的加密库里。服务端的同步接口其实写好了，但开关默认关着，iOS 也没接。

这意味着，Web 和小程序上「今天」「成长」「我们家」这几页，打开只能是空的。

负责验收的 Agent 指出，这不是工程量的问题：接通同步，就等于把这些家庭数据搬上服务端，隐私边界变了。验收单因此单列了一组「家庭同步门」，包括双向同步、冲突处理、迁移不丢数据、用户同意、按家庭隔离权限、删除联动。

这个问题被摆到我面前时，和另一个问题一起问的。我只回了一个「A」，统筹的 Agent 没有自己认定 A 就是「接通同步」，而是回问我 A 对应的是哪一题。最后只落实了我明确说清的那一条：Web 不开匿名，只用第三方账号登录。家庭同步至今还没定。

没定也没停工。写入类的功能先不做，这几页先做「同步未开启」的空态，设计两版都画，代码只做不依赖这个决定的部分。

## 照实说现在的状态

第一批 Web 代码已经合进了主干。验收单和四端对照表都交了。可 Web 还没有部署，也没有可以点开的预览，所以首轮实机回归一行都还没跑。小程序的骨架还是草稿。

所以我现在不能说 Web 版做完了，更不能说它没有降级。我能说的是，「不降级」这三个字已经变成了 148 行可以逐条判对错的条目。等预览环境开出来，每一行都会有一个结果。
