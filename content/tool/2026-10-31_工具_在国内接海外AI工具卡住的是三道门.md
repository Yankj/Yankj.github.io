> 配置里写的是最强的模型，实际跑的是 Flash，命令行一个字都没报错。

这两天我让 Agent 在一台电脑上接谷歌的 Antigravity 命令行（`agy`），想通过谷歌账号登录来用 Gemini，默认用当时最强的 Gemini 4 Argon。

安装很顺，登录也很顺。可最后的结论是：没做成。命令行装好了，账号登上了，就是不能拿来推理。

整个过程里，真正卡住的不是技术，而是三道门：订阅、账号地区、网络出口。它们一道接一道，前一道不过，你根本看不到后一道。我把这次的排查顺序记下来，接别的海外 AI 工具时大概也是这个路数。

## 先定一条规则：不拿 API Key 当默认路径

动手之前，我先定了一条规则：走谷歌账号的 OAuth 登录，不把 API Key 当默认路径，配置里也不写死模型提供方，免得绕过账号登录直接走 Key。

原因很简单。账号登录和 API Key 是两条不同的路，权益不一样。我想用的是账号订阅里带的模型，API Key 那条路本身也拿不到这份订阅权益。一开始就混着用，后面出了问题，根本分不清是哪条路的问题。

## 第一道门：订阅。写了模型名，不等于真在用

安装完成，OAuth 登录成功，配置文件里也写上了 `gemini-4-argon`。一切看起来都对。

可用 `agy models` 列模型时，列表里只有 Flash、Claude 和 GPT-OSS，没有 Argon。写了 Argon 的配置会被静默降级到 Flash，命令行不报任何错。

如果不去对照模型列表，你会一直以为自己在用最强的模型。查下来，官方要求付费的 Google AI Pro 或者 Ultra 订阅，试用不算，而账号的订阅页显示没有订阅。

这道门的教训是：服务端不发这个模型时，客户端不一定会告诉你。接任何工具，第一件事都是去列「你实际能用的模型」，而不是相信配置文件里写的那个名字。

## 第二道门：账号地区。改时区没用

能列出模型以后，一推理（`agy -p`）就报地区不可用。

第一反应是改时区，没用。去翻官方的说明才知道，判定依据是谷歌账号服务条款里的「关联国家」，这和电脑的时区、系统语言都无关。中国大陆不在可用地区里。

我当时连着问了几句：「如何修改地区」「新加坡可用吗」。谷歌提供了修改关联国家的申请表单，我改成了一个在可用范围内的地区，然后说：「google账号的国家改了，你再试试看」。

## 第三道门：网络出口。账号过了，请求还是被拒

改完以后，报错的文案变了，从「账号地区不可用」变成了：

`User location is not supported for the API use.`

这个变化本身就是一条线索：账号这一侧已经过了，被拒的是请求发出时的网络出口位置。

到这一步，我问过一句：「你有别的地方的电脑吗」。可这条路我们没有走下去，事先定过的规则是不绕过地区门禁。这条线就此搁置。

## 排查顺序可以复用

把这次的过程抽出来，接任何有地区限制的海外 AI 工具，都可以按这个顺序查：

| 顺序 | 查什么 | 怎么确认 |
|---|---|---|
| 1 | 订阅：这个模型你的账号能不能用 | 列出实际可用的模型，对照账号订阅页，不看配置文件 |
| 2 | 账号地区：账号关联的国家在不在可用范围 | 看官方关于可用地区的说明和账号的关联国家，不看时区 |
| 3 | 网络出口：请求从哪里发出 | 看报错文案是否从「账号」变成「位置」 |

有两个细节值得记住。第一，每过一道门，报错的文案都会变，文案变化就是你前进了一步的证据，别因为「还是报错」就以为白改了。第二，静默降级是最危险的失败，因为它看起来像成功。

## 没做成，也是一个结论

这件事最后没有做成，我也没打算为它破例。规则写得很清楚：不绕过地区门禁，也不默认改走 API Key。

我把它写下来，是因为这类问题在国内用 AI 工具时太常见了。很多「装不上」「用不了」，其实装得好好的，卡在的是账号、订阅和网络这些不在代码里的东西。先把这三道门分清楚，至少能少花几个小时在错误的方向上，比如反复改时区。

参考的官方页面：[Antigravity 模型说明](https://antigravity.google/docs/models/)、[Google 服务条款](https://policies.google.com/terms)、[账号关联国家申请表](https://policies.google.com/country-association-form)。
